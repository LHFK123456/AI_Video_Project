# 高频踩点视频生成器

音频驱动的高频踩点视频工具。文字、背景、频谱全部由**真实音频分析**驱动，不是按秒数硬编码动画。

---

## 快速开始

### 方式一：拖拽（最简单）

把音频文件拖到 `一键出片.bat` 图标上，按提示输入标题，成品出现在 `out` 文件夹。

### 方式二：命令行

```bash
node make.mjs assets/song.mp3 --title "歌名" --size all
```

### 方式三：可视化调参

```bash
npm run dev
```

浏览器打开 Remotion Studio，可以实时拖动时间轴、改颜色、调参数，所见即所得。

## 它到底怎么"踩"的

这不是简单按 BPM 均分时间，流程是：

**1. 解码** — ffmpeg 把音频转成 22050Hz 单声道 PCM

**2. STFT 频谱分析** — 窗长 1024、跳距 256，得到每秒 86 帧的频谱

**3. 谱通量起音检测** — 计算相邻帧各频段能量的正向增量（spectral flux），这是判断"有没有鼓点"的关键：鼓点会带来宽频段的能量突增

**4. 自适应阈值找峰** — 用局部窗口的均值 + 1.15 倍标准差作为动态阈值，适应音量变化

**5. 亚帧精度修正** — 这一步决定了踩点准不准：
- **抛物线插值**：在峰值前后帧拟合抛物线，得到帧间精度
- **窗中心校正**：STFT 的能量峰值出现在窗中心而非窗起点，必须补偿 `1024/2/22050 ≈ 23ms`

修正前误差 28ms（约 0.84 帧），修正后 **6.8ms**

**6. BPM 估测** — 对 60~200 BPM 扫描，找与拍点间隔（含 1/2、2、3、4 倍关系）最吻合的速度

**7. 弹簧驱动渲染** — 每拍触发一次 Remotion 的 `spring()`，产生真实的回弹而非线性缩放

## 视觉层构成

| 层 | 驱动源 | 效果 |
|---|---|---|
| **主标题** | 逐字独立响应节拍 | 弹簧回弹缩放、向上跳跃、发光、轻微倾斜 |
| **入场** | 首个强拍 | 逐字错开落下，弹性回弹 |
| **背景光晕** | 强拍 + 音频能量 | 径向扩散、色带流动 |
| **网格** | 底鼓脉冲 | 缩放外推、透明度呼吸 |
| **音浪涟漪** | 每拍一圈 | 向外扩散并消散 |
| **频谱条** | 48 段真实频率能量 | 底部柱状，低频高高频低 |
| **歌词** | 句子时间轴 | 逐字点亮（卡拉OK式） |
| **镜头** | 音频能量 | 轻微推拉 + 强拍震动 |
| **白闪** | 底鼓 | 强拍瞬间闪白 |
| **扫描线** | 静态 | 增加质感 |

标题的**每个字都有相位差**（`beatOffset`），所以不是整块一起缩放，而是像波浪一样依次跳动——这是"高级感"的关键细节。

## 验证工具

不靠肉眼，用数据验证：

```bash
# 帧间差异分析：确认动效真的在动
node scripts/verify-frames.mjs out/xxx.mp4

# 踩点精度：逐拍比对，算命中率
node scripts/verify-sync.mjs out/xxx.mp4
```

`verify-sync` 的原理：比较"鼓点帧的画面变化"与"鼓点前几帧的基线变化"。若动效真由音频驱动，前者应显著大于后者。

当前测试结果：**32 拍中命中 31 拍（97%）**，平均变化倍数 8.14x。

## 常见问题

**Q: 踩点不准怎么办？**
先跑 `node scripts/analyze-beats.mjs 音频 --fps 30` 看 BPM 估测是否合理。电子音乐、流行歌通常很准；自由节奏（古典、人声清唱）的 BPM 估测意义不大，但拍点本身仍然可用。

**Q: 想更细腻？**
加 `--fps 60`。60fps 下每拍有更多帧，弹簧回弹更平滑，但渲染时间翻倍。

**Q: 动效太猛/太弱？**
调 `--intensity`，范围 0.4（克制）到 2（夸张）。

**Q: 中文标题显示不出来？**
渲染用 Chromium，中文字体由系统提供，Windows 自带微软雅黑，正常可用。

**Q: 想改用我自己的字体？**
在 `src/BeatVideo.tsx` 里给 `fontFamily` 加字体名，或把字体文件放 `public/` 用 `@font-face` 引入。
